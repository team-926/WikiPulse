# PulseMap 확대·축소 최적화

2026-09-17 · WP-122, WP-125. 기존 네온 디자인을 유지하고 카메라 프레임의 반복 작업을 줄였다.

## 적용 내용

1. 카메라 보간 중 React 전체 지도 렌더를 제거했다. ref/구독자로 프레임을 전달하고, 줌 안정 또는 드래그 종료 시 React 상태를 반영한다. 클러스터를 memo 컴포넌트로 분리했다.
2. 제목 글꼴·박스 치수·줄바꿈을 고정하고 그룹 transform으로 기존 완만한 배율을 구현한다. 문서 라벨은 줌 중 scale로 보정하고 정지 시 줄바꿈을 정리한다.
3. 화면 크기·카메라·제목 경계를 계산해 140 화면 px 밖의 클러스터를 `display:none` 처리한다. 데이터와 전체 DOM은 보존하며 재진입하면 복원한다. 숨겨진 클러스터는 탭 이동과 스캔 갱신에서도 제외한다.
4. 스캔 대상 거리를 정렬하고 파동·잔광 범위를 이진 탐색해 현재 보이는 대상만 갱신한다. 이전에 켜졌던 잔광만 추적해 해제한다. 제목의 현재 중심 좌표, 4초 주기, 600ms 잔광, 일시정지·모션 감소·화면 밖 중단은 유지한다.
5. 카메라와 스캔의 프레임 처리에서는 배치를 유발하는 DOM 측정 없이 속성을 갱신한다. 휠 입력의 중복 `getScreenCTM()` 호출도 제거했다.

카메라와 스캔은 각각 RAF를 사용한다. 단일 스케줄러로 합치지는 않았으며, 프레임 갱신 사이의 배치 읽기를 제거하고 현재 가시성 집합을 공유한다.

## 전후 측정

[수정 전 진단](REPORT.md)과 같은 production mock, headless Chromium 1440×1000 전체화면, 36개 클러스터·318개 노드·282개 간선, 휠 입력 24회, CPU 추가 제한 없음. 각 2회 평균이다. 실제 화면 표시 FPS나 사용자 기기의 성능 보장으로 해석하지 않는다.

| 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| rAF 처리 빈도 | 29.56 fps | 44.71 fps |
| p95 프레임 간격 | 50.05 ms | 33.40 ms |
| 동일 입력 시나리오 소요 시간 | 5.62초 | 4.26초 |
| Script 시간 | 0.703초 | 0.072초 |
| Style 계산 시간 | 0.522초 | 0.123초 |
| Layout 시간 | 2.558초 | 2.755초 |
| 전체 Task 시간 | 5.460초 | 3.883초 |

평균 rAF 빈도는 약 51% 높아졌다. JavaScript와 스타일 계산은 감소했지만 Layout 누적 시간은 감소하지 않았다. 더 많은 프레임을 처리한 결과와 프레임당 배치 비용을 분리해야 하며, SVG/foreignObject의 브라우저 배치는 여전히 주요 비용이다.

별도 Observer/CPU profiler 계측 실행의 DOM 속성 변경은 130,823 → 14,981건(약 89% 감소), 제목 관련 변경은 96,048 → 3,931건(약 96% 감소)이었다. 같은 실행의 카메라 갱신 수는 132 → 168회로 서로 다르므로 속성 건수를 CPU 시간 절감률로 해석하지 않는다. 줌 중 제목 rect의 x/y/width/height/rx 반복 변경은 사라졌다.

4× CPU 감속 결과는 수정 전 약 5.64fps, 수정 후 4.79/8.69fps로 편차가 컸다. 저사양 환경에서 일정한 개선율이나 60fps 달성을 주장하지 않는다. 추가로 문서 라벨 containment, 줌 중 라벨 transform 제거를 각각 2회 시험했으나 약 44~45fps로 차이가 작아 제품 코드에는 적용하지 않았다.

## 기능 검증

- ESLint 및 production mock build 통과.
- Pulse E2E 18개 최종 통과: 기존 16개 + 최적화 회귀 2개. 초기 실행에서 화면 밖 DOM의 기하 측정/키보드 포커스 가정을 현재 표시 영역에 맞췄으며, 신규 테스트의 비활성 축소 버튼 재클릭은 실제 휠 입력으로 수정한 뒤 2개 재실행을 통과했다. 전체 18개 단일 실행 완료를 뜻하지 않는다.
- API 모드 Pulse 6개 통과. 500개 노드·1,000개 간선 선택·이동 포함. HTTP 응답 가로채기이며 Spring/DB 통합 검증은 아니다.
- 데스크톱 1440px·모바일 390px 전체화면 기본/줌 캡처 확인. 글자·박스·빛번짐 유지, 가로 넘침 없음, 페이지 JavaScript 오류 없음.
- 호의 마우스 방향 회전, 제목 스캔 글로우, 드래그 시 흰 외곽선 없음 확인.
- 줌 경계·포인터 기준 확대, 전체화면 전환, 제목의 완만한 배율, 노드 내부 라벨, 숨겨진 클러스터 복귀, 전체 노드 유지, 모션 감소·일시정지·키보드 선택을 회귀 검사했다.

## 재현과 자료

MR 제출 전 최신 develop(`af298a7`)을 반영한 `d521b33`에서 전체 E2E 43/43, API 계약 E2E 13/13을 한 번씩 실행해 통과했다. 위의 개발 중 분리 실행 기록을 보완하는 최종 검증이다. lint, 데이터·계약 검사와 build도 통과했다.

`pulse-zoom-audit.mjs`에서 `PULSE_AUDIT_URL`로 preview 주소, `PULSE_AUDIT_NAME`으로 파일 접두사를 지정한다. `--baseline-only`는 CPU 1×/4× 각 2회와 별도 profile을 실행한다. 기본 접두사를 그대로 쓰면 이전 결과를 덮어쓰므로 전후 비교에는 서로 다른 값을 사용한다.

- 수정 전: `zoom-results.json`, `profile-summary.json`, `baseline.cpuprofile`.
- 수정 후: `after-zoom-results.json`, `after-profile-summary.json`, `after-baseline.cpuprofile`.
- 라벨 추가 실험: `label-check-zoom-results.json`.
- 화면/상호작용 확인: `verify-optimized-view.mjs`, `optimized-1440-*.png`, `optimized-390-*.png`.
- 제품 계약: [PULSE_MAP.md](../../docs/frontend/PULSE_MAP.md), [DESIGN.md](../../docs/design/pulse-map/DESIGN.md).

측정용 build는 `.impeccable/performance-dist`(수정 전), `.impeccable/performance-after`(수정 후)에 따로 보관했다. 사용자 환경 파일은 변경하지 않았다.
